# 部分恢复旋转范围设计

## 1. 规范关系与决策依据

- 唯一核心设计基准仍是 `基于目标器官的采样方法-20260806.docx`，SHA-256 为 `4b27aee1a6db1680e501f17bd3492a571bd169c0bf7004d79b4a512d929cc53b`。
- 核心设计文件原始范围为滚转 `[-45, +45]` 度、俯仰 `[-30, +30]` 度，步长均为 5 度；此前用户明确将两轴收窄为 `{-5, 0, +5}` 度。
- 2026-08-08，用户在确认服务器原始网格未被低模化、病例 2 的 400 个点由 10 mm 最小间距约束产生，并获知各角度方案的产出规模后，批准部分恢复方案：滚转 `[-15, +15]` 度、俯仰 `[-10, +10]` 度，步长均为 5 度。
- 本规范只覆盖 `2026-08-07-core-design-alignment-design.md` 的滚转和俯仰范围及其派生姿态数。核心设计文件本身不被改写，偏航规则和其他设计条款继续有效。

## 2. 目标与非目标

### 2.1 目标

- 在不改变采样点的前提下，增加每个点在 0 度面附近的滚转和俯仰覆盖。
- 保持三类偏航范围与核心设计文件一致。
- 由实际角度数组动态计算姿态数，禁止继续使用只适用于 3 x 3 组合的常数 `9`。
- 在元数据、中英文文档和运行日志中准确记录受控变更后的角度范围。
- 在服务器磁盘、内存和 GPU 约束下，以独立输出目录运行且保留可回退能力。

### 2.2 非目标

- 不修改病例 2 的原始 CT、器官 PLY、血管模型或配准模块。
- 不修改采样候选筛选、点数上限、确定性 FPS、10 mm 最小间距或当前 400 个实际采样点。
- 不修改普通、十二指肠球部和胰腺特殊区的偏航范围。
- 不修改 0 度基准面、局部坐标轴、旋转顺序、100 mm 方形或 300 x 300 CT 重采样参数。
- 不恢复滚转 `[-45, +45]` 度和俯仰 `[-30, +30]` 度的完整范围。
- 不新增可由病例任意覆盖的角度配置接口；本次变更是项目级固定算法决策。

## 3. 角度与旋转语义

各采样点继续以既有右手局部坐标系的 0 度面为基准，并执行完整笛卡尔积：

| 轴 | 新范围 | 步长 | 数量 |
| --- | --- | ---: | ---: |
| 滚转 roll | `[-15, +15]` 度 | 5 度 | 7 |
| 俯仰 pitch | `[-10, +10]` 度 | 5 度 | 5 |
| 普通偏航 yaw | `[-30, +30]` 度 | 5 度 | 13 |
| 十二指肠球部偏航 yaw | `[-90, +90]` 度 | 5 度 | 37 |
| 胰腺特殊区偏航 yaw | `[-120, +30]` 度 | 5 度 | 31 |

旋转矩阵和作用方式保持为 `B' = B (Rz @ Ry @ Rx)`。因此每点姿态数分别变为：

- 普通区域：`7 x 5 x 13 = 455`
- 十二指肠球部：`7 x 5 x 37 = 1295`
- 胰腺特殊区：`7 x 5 x 31 = 1085`

角度序列必须包含 0 度、关于 0 度对称且包含两个端点。稳定姿态 ID 继续记录实际 `roll`、`pitch` 和 `yaw`，完全相同四顶点的严格去重规则不变。

## 4. 病例 2 规模与资源门槛

服务器只读 dry-run 得到 400 个采样点，其中普通策略 364 个、十二指肠球部策略 17 个、胰腺特殊策略 19 个。因此变更后的候选姿态总数为：

```text
364 x 455 + 17 x 1295 + 19 x 1085 = 208250
```

当前 53,550 个姿态对应的放大系数为 `208250 / 53550 = 3.889`。按既有导出结果的平均记录大小 `81,980.19 bytes/record` 估算，新结果约为 17.1 GB。正式运行前继续执行磁盘安全门槛：

```text
预计结果字节数 x 1.25 + 5 GiB <= 输出卷可用空间
```

该门槛约为 24.9 GiB；2026-08-08 dry-run 后输出卷可用空间约为 39.0 GiB。估算只能用于放行判断，不能替代运行中的磁盘监控。

服务器继续使用 `workers: 4`、`gpu_batch_size: 8`。正式运行前必须先完成新角度 dry-run，同时监控进程 RSS、90 GiB cgroup 内存、OOM 事件、GPU 显存和数据盘余量。任何资源门槛失败均停止，不自动缩小角度、减少点数或覆盖历史输出。

## 5. 实现边界

- 在姿态定义模块中将滚转常量改为 7 个值，将俯仰常量改为 5 个值；偏航常量不变。
- 姿态候选数必须使用 `len(ROLL_ANGLES_DEGREES) * len(PITCH_ANGLES_DEGREES)` 动态推导，不能写死为 `35`，更不能保留旧值 `9`。
- `generate_pose_variants` 继续遍历 yaw、pitch、roll 并使用既有矩阵语义，不修改局部坐标构造。
- 运行元数据继续直接从角度常量生成范围，因此元数据必须自动反映新值。
- 不修改 YAML 配置模式。配置示例和中英文文档将角度标记为本次用户批准的项目级受控决策，而不是核心设计文件的完整原范围。

## 6. 失败保护与输出隔离

- 姿态预估数与实际生成数不一致时继续抛出错误，不进入渲染。
- 新范围必须通过角度集合、矩阵正交性、右手性、姿态 ID 唯一性和精确总数测试。
- 服务器更新前重新备份当时的 `project/` 和 `run/`，校验压缩包、成员路径和 SHA-256。
- 修复分支继续与 `main` 隔离；只推送该分支，不合并 `main`。
- 新结果写入独立且原先不存在的输出目录，不覆盖 43,695 个历史模型或任何先前 dry-run 记录。
- 正式运行前核对 Git commit、病例配置哈希、核心设计文件哈希、208,250 姿态总数和磁盘门槛。

## 7. 测试与验收

实现按测试驱动顺序完成：

1. 更新角度测试，要求滚转精确等于 `{-15, -10, -5, 0, 5, 10, 15}`，俯仰精确等于 `{-10, -5, 0, 5, 10}`，三类偏航集合保持不变。
2. 要求普通、十二指肠球部和胰腺特殊区每点姿态数分别为 455、1295 和 1085。
3. 增加候选数动态推导回归测试，防止再次出现写死的 `9` 或 `35`。
4. 保留 0 度姿态、旋转矩阵、右手正交系、四顶点几何和严格去重测试。
5. 更新运行元数据测试，要求完整记录新的滚转和俯仰数组，偏航数组不变。
6. 更新仓库 README、配置示例说明及桌面中英文说明文档；生成的 HTML 必须与 Markdown 内容一致。
7. 运行完整本地测试集，并确认除预期文档和实现文件外没有工作区污染。
8. 推送修复分支，备份并更新隔离服务器项目后运行完整服务器测试集。
9. 使用病例 2 配置执行只读 dry-run，验收采样点仍为 400、各区域点数不变、最小间距仍至少为 10 mm、姿态总数为 208,250，且没有 OOM 或输出写入。
10. dry-run、磁盘门槛和用户运行批准全部满足后，才启动完整 GPU 重采样；结束后核对 manifest 各状态互斥且合计为 208,250。

# CT-EUS Manual Segmentation and Expanded Full Resampling

面向 EUS 图像检索图库构建的可复现 CT 医学影像重采样管线。论文版本只保留两条正式能力：从手工 3D Slicer `.seg.nrrd` 准备输入，以及按 2026-08-13 基准设计与 2026-08-19 正式修订执行三轴完整重采样。

This repository provides a reproducible CT-to-EUS resampling pipeline for retrieval-gallery construction. The paper release intentionally retains only manual-segmentation input preparation and expanded full resampling.

> Research software only. This project is not a medical device and must not be used for clinical diagnosis or treatment decisions.

## Method Summary / 方法概述

- CT 与标签体必须共享 `Size`、`Spacing`、`Origin` 和 `Direction`；输入 LPS 物理坐标在计算边界统一转换为 RAS，体素数据不被预先重排。
- 胃、肝、胰腺、十二指肠和食管先限定到最大闭合主外壳，再按设计规则筛选采样区域并执行确定性 FPS；同一器官合并点集的最小 RAS 欧氏距离为 `10 mm`。配置点数是上限，外表面无法满足数量时不降低间距补点。
- 每个采样点是探头位置，并始终位于 `100 mm x 100 mm` 方形底边中点。旋转围绕该点进行，探头位置不移动。
- 局部内禀旋转顺序为 `B' = B @ Rz(yaw) @ Ry(pitch) @ Rx(roll)`：
  - roll：`-45..+45 degrees`，步长 `5 degrees`；
  - pitch：`-30..+30 degrees`，步长 `5 degrees`；
  - standard yaw：`-30..+30 degrees`，步长 `5 degrees`；
  - liver-region-two yaw：`-60..+60 degrees`，步长 `5 degrees`；
  - duodenal-bulb / pancreas-special yaw：`-120..+30 degrees`，步长 `5 degrees`。
- 普通点每点产生 `3211` 个姿态，肝脏二区点产生 `6175` 个姿态，十二指肠球部和胰腺特殊偏航点产生 `7657` 个姿态；四顶点在 `atol=1e-9 mm` 下完全相同时精确去重。
- CT 使用患者世界坐标三次 B-spline 插值；手工标签体在同一方形上使用最近邻插值。
- 黑色像素比例只有在严格 `> 0.60` 时按比例规则拒绝，恰好 `0.60` 保留；直线黑边规则独立执行。

The implementation preserves native CT geometry, converts LPS inputs to canonical RAS at the physical-coordinate boundary, and samples CT and labels on exactly the same world-coordinate plane.

## Environment Setup / 环境安装

Python `3.12` is required. Scientific and GPU dependencies are managed with `mamba`.

CPU:

```bash
mamba env create -f environment.yml
mamba activate ct-vessel-resampling
python -m pip install -e .
```

GPU:

```bash
mamba env create -f environment.gpu.yml
mamba activate ct-vessel-resampling-gpu
python -m pip install -e .
```

The GPU backend uses CuPy and is calibrated against the CPU reference before production sampling. `runtime.backend: auto` falls back to CPU if GPU initialization or calibration fails; `gpu` fails explicitly instead of silently changing backends.

The formal server environment was validated with Python 3.12, SimpleITK 2.5.5, NumPy 2.5.1, SciPy 1.18.0, scikit-image 0.26.0, trimesh 4.12.2, rtree 1.4.1, Pillow 12.3.0, PyYAML 6.0.3, OpenCV 5.0.0, Plotly and CuPy 14.1.1 on an NVIDIA RTX 4080 SUPER. Plotly is required only for `paper_figures/` and its tests; a minimal core installation may omit the `paper` extra.

## Input Data / 输入格式

Recommended case layout:

```text
data/case_001/
├── ct.nrrd                         # or ct.nii / ct.nii.gz / DICOM directory
├── EUS-main-organ.seg.nrrd         # manual integer label volume
├── artery_tree.ply                 # existing reconstructed artery model
├── vein_tree.ply                   # existing reconstructed vein model
└── prepared/                       # generated by the preprocessing command
```

The manual label volume must contain the 14 required organ structures. The paper contract additionally derives three EUS vessel classes:

| Class | Source label values | RGB |
|---|---:|---:|
| Aorta | `8` | `[255, 0, 0]` |
| Inferior vena cava | `9` | `[0, 0, 255]` |
| Portal venous system | `26, 33, 34, 35, 36, 37` | `[170, 85, 255]` |

Main portal vein label `23` contributes to the portal-vein organ union but not to the three-class EUS vessel feature set. SMV label `26` contributes to both. Bile duct labels are excluded from organ metadata.

The existing `artery_tree.ply` and `vein_tree.ply` remain the source of the original vascular `features`, Gallery routing, `boundary_only` images and CT overlays. They must use the same patient physical coordinate system declared by `geometry.input_coordinate_system`.

## Quick Start / 完整运行

### 1. Prepare a manual case

For NRRD/NIfTI CT:

```bash
python scripts/preprocess_manual_segmentation_case.py \
  --ct data/case_001/ct.nrrd \
  --segmentation data/case_001/EUS-main-organ.seg.nrrd \
  --artery-model data/case_001/artery_tree.ply \
  --vein-model data/case_001/vein_tree.ply \
  --output data/case_001/prepared \
  --output-root output \
  --case-id case_001
```

For a DICOM directory containing multiple series, additionally pass the explicitly reviewed Series UID:

```bash
python scripts/preprocess_manual_segmentation_case.py \
  --ct data/case_001/dicom \
  --dicom-series-uid 1.2.840.example \
  --segmentation data/case_001/EUS-main-organ.seg.nrrd \
  --artery-model data/case_001/artery_tree.ply \
  --vein-model data/case_001/vein_tree.ply \
  --output data/case_001/prepared \
  --output-root output \
  --case-id case_001
```

This command validates CT/segmentation geometry, creates 14 organ masks and physical-space PLY meshes, copies the source segmentation byte-for-byte, records SHA-256 provenance, and writes `case_manual_segmentation.yaml`. The destination must be empty unless `--overwrite` is explicitly supplied.

### 2. Review and dry-run

Review the generated YAML, especially coordinate-system declaration, vessel paths, output root and any manually confirmed duodenal centerline endpoints.

```bash
ct-vessel-resampling \
  --case-config data/case_001/prepared/case_manual_segmentation.yaml \
  --dry-run
```

Dry-run computes the actual sampling points and pose count without writing a library.

### 3. Run expanded full resampling

```bash
ct-vessel-resampling \
  --case-config data/case_001/prepared/case_manual_segmentation.yaml \
  --steps all \
  --workers 4 \
  --backend auto \
  --gpu-device 0 \
  --gpu-batch-size 8
```

`all` executes sampling, square-pose generation, rendering/filtering, internal Gallery validation and `library_summary.json` generation. No external `2021.py` module is required.

### 4. Resume and audit

Normal reruns resume only after strict comparison of configuration, input hashes, design hash, pose geometry and completed manifests. If a signal terminated the process before `run_metadata.json` was written, rebuild metadata only with independently verified evidence:

```bash
python scripts/recover_interrupted_run_metadata.py \
  --case-config data/case_001/prepared/case_manual_segmentation.yaml \
  --expected-completed-count 100000 \
  --reason sighup \
  --exit-code 129
```

Then audit a completed library:

```bash
python scripts/audit_resampling_output.py \
  output/case_001 \
  --case-config data/case_001/prepared/case_manual_segmentation.yaml \
  --report output/case_001/audit_report.json \
  --check-pixels
```

审计命令默认要求当前正式设计哈希；它会逐点核对 PLY 坐标/法线、从真实输入独立重建局部基准轴、复算运行协议摘要、检查完整角度笛卡尔积、精确去重来源姿态以及根/状态清单内容。使用人工十二指肠中心线时必须通过 `--case-config` 提供输出目录外的原病例 YAML，以锁定经病例确认的近端和远端。旧库必须显式传入其已确认的设计哈希，不能以未知哈希降级通过。

## Outputs / 输出结构

```text
output/case_001/
├── gallery/
│   ├── ct/
│   ├── boundary_only/
│   ├── ct_overlay/
│   ├── organ_vessel_boundary/
│   ├── eus_vessel_boundary/
│   ├── ct_eus_vessel_overlay/
│   └── gallery.jsonl
├── unindexed/                      # quality-passing planes without original vessel features
├── rejected/                       # quality-rejected planes
├── excluded_fov/                   # planes exceeding the native CT physical FOV
├── manifest.jsonl                  # all terminal states
├── run_metadata.json               # reproducibility and resume protocol
└── library_summary.json            # internal validated index summary
```

For manual labels, one sampled organ pixel is sufficient for `organ_labels`; a closed contour is not required, and a plane fully inside an organ is labelled. For the three EUS vessel features, edge-touching or open components remain visible in boundary and overlay images but are excluded from `eus_vessel_features`.

`gallery.jsonl` is the stable downstream exchange interface. This repository validates and summarizes it but intentionally does not vendor a retrieval engine or convert records into external application-specific classes.

## Offline GPU Server Deployment / 离线服务器部署

On an internet-connected workstation:

```bash
git clone <repository-url> ct_vascular_resampling
cd ct_vascular_resampling
git checkout <validated-release-tag>
git archive --format=tar.gz --output=ct_vascular_resampling.tar.gz <validated-release-tag>
```

正式服务器只部署已提交并通过完整测试的固定 tag/commit；不得从脏工作树打包，否则运行元数据中的构建提交不能代表实际代码。

Create the mamba environment on a compatible online machine and package it with `conda-pack`, or manually transfer an existing validated environment. Transfer the source archive, packed environment and case data to the offline GPU server. Extract them into separate project and data directories; do not embed case data in the Git repository.

After unpacking on the server:

```bash
source /path/to/environment/bin/activate
python -m pip install --no-deps -e /path/to/ct_vascular_resampling
ct-vessel-resampling --help
pytest -q /path/to/ct_vascular_resampling/tests
```

Use absolute paths in the private case YAML when code and data are stored on different disks. Never publish DICOM UIDs, patient identifiers, credentials or server-specific absolute paths.
